# CarlasHub profile visibility plan

The profile now has a clear positioning statement, six proof-oriented flagship projects, working demos, relevant case studies, skills, and contact routes. The next improvements should reinforce that same story everywhere rather than add more unrelated material.

## Now: make the profile coherent

- Pin the same six flagship repositories shown in the profile README.
- Give every flagship repository a consistent one-line description, HTTPS homepage, focused topics, and social-preview image.
- Add a short “Part of the CarlasHub portfolio” link from each flagship README back to `https://carlashub.com/`.
- Keep experimental and learning repositories public when useful, but do not feature them above the strongest evidence.

## Next 7 days: turn visits into understanding

- Add one 60–90 second captioned demo to each flagship project.
- Use the same case-study structure: problem, constraints, decisions, implementation, evidence, outcome, and next step.
- Create a Work page on CarlasHub that mirrors the six-project shortlist and links in both directions.
- Add the profile and two strongest case studies to LinkedIn's Featured section.

## Next 30 days: build discoverability

- Standardise project titles and descriptions around search language people use: accessibility testing, WCAG 2.2, Playwright, site crawler, AI-agent governance, and MCP.
- Publish focused articles that link to one live demo and one repository instead of broad roundups.
- Add valid canonicals and sitemaps to every public project site, then request indexing for flagship URLs.
- Earn a small number of relevant links through accessibility, QA, open-source, and responsible-AI communities.

## Measure what works

- GitHub profile views and repository traffic for the six flagships.
- Clicks from the GitHub profile to CarlasHub, identifiable through the `github / profile` campaign parameters.
- Search Console impressions and clicks for branded terms (`CarlasHub`, `Carla Goncalves`) and flagship topics.
- Demo starts, case-study reads, stars, forks, and meaningful enquiries—not repository count alone.

Review the shortlist quarterly. Replace a flagship only when another project has stronger proof, a clearer outcome, or materially better audience relevance.
